# PROJECT: INNOVATION & PROJECT SUBMISSION MANAGEMENT SYSTEM
## Premium Frontend UI/UX Design — Awwwards-Inspired Institutional Web Application

Act as a world-class Senior Product Designer, UI/UX Designer, Design Systems Engineer, and Senior Frontend Developer.

Your task is to design and build a complete, polished, responsive, interactive frontend prototype for an **Innovation and Project Submission Management System** based on the functional requirements below.

The design must have the visual quality of a premium SaaS product featured on Awwwards, while maintaining the clarity, usability, accessibility, and professionalism expected of a university or institutional workflow management platform.

This is a frontend-only project. Do not build a backend, create a real database, configure authentication servers, or connect to external APIs. Use realistic mock data and browser-side state to demonstrate how the system would work.

Do not produce only a landing page, static mockup, or collection of disconnected screens. Build a coherent, navigable web application with multiple pages, interactive controls, realistic data, and a consistent design system.

---

# 1. PROJECT BACKGROUND

The system manages the reception, documentation, fact-finding, review, refinement, and routing of student projects and general innovation ideas.

The requirements were gathered during a meeting with Mr. Kaddu Titus on 14 October 2026.

The system must accommodate two distinct submission categories:

1. Student Projects
2. General Innovations

Student projects require a project code for identification and tracking. General innovation submissions must follow their own appropriate pathway and must not automatically be subjected to student-specific requirements.

The receptionist serves as an initial receiving and routing point. Designated personnel examine project briefs, review supporting documents, identify missing information, forward submissions to relevant sectors, and provide constructive feedback.

Ideas that need improvement should generally be guided through refinement rather than rejected immediately.

The system may involve multiple reviewers, an Intellectual Property (IP) destination, and several institutional sectors. The precise organizational roles and workflow transitions are not yet confirmed, so make these elements configurable in the frontend rather than assuming an unchangeable process.

## Core product objective

Create a centralized workspace where authorized personnel can:

- Register incoming projects and innovation ideas.
- View and search submissions.
- Track project codes and submission statuses.
- Review project briefs and supporting documents.
- Identify missing information.
- Assign submissions to responsible personnel or sectors.
- Route briefs to Intellectual Property where appropriate.
- Record reviews, recommendations, and constructive feedback.
- Return submissions for refinement.
- Track revisions and resubmissions.
- Inspect the activity history of each submission.
- Monitor workflow progress through a clear dashboard.

The system should communicate trust, accountability, innovation, efficiency, and institutional professionalism.

# 3. VISUAL DESIGN DIRECTION

Create a sophisticated, editorial, contemporary institutional dashboard.

The visual quality should combine the refined aesthetic of a premium fintech dashboard, the visual storytelling of an Awwwards-quality digital product, and the usability of a professional enterprise application.

Do not imitate a particular existing product screen. Develop an original design language.

## Color palette

Use a restrained, premium palette:

- Primary background: warm off-white, approximately #F8F8F5.
- Main surface: white, approximately #FFFFFF.
- Primary text: deep charcoal, approximately #171A19.
- Secondary text: muted slate, approximately #747A78.
- Primary accent: deep forest green, approximately #176B52.
- Secondary accent: lime or soft chartreuse, approximately #D9F27A.
- Border: subtle warm gray, approximately #E7E9E4.
- Information: muted blue.
- Warning: warm amber.
- Error: restrained red.
- Success: forest green.

Use green as the primary institutional accent. Use chartreuse sparingly for active indicators, highlights, or selected elements.

Do not make every element colorful. Most of the interface should use neutral surfaces, clear typography, whitespace, and subtle borders.

## Typography

Use a modern, high-quality type pairing such as:

- Headings: Manrope or Plus Jakarta Sans.
- Body text: Inter.

Use strong typography hierarchy, carefully controlled font weights, clear labels, comfortable reading sizes, and well-spaced headings.

Large page headings should feel intentional and editorial without sacrificing information density.

## Layout

Use:

- A persistent desktop sidebar.
- A compact top navigation bar.
- A responsive mobile navigation drawer.
- Spacious dashboard layouts.
- Clear page titles and contextual descriptions.
- Well-designed cards with subtle borders.
- Refined tables with comfortable row spacing.
- Attractive empty states.
- Skeleton loading states where appropriate.
- Contextual action menus.
- Breadcrumbs on detail pages.
- Toast notifications for successful prototype actions.

Avoid excessive rounded cards, heavy shadows, unnecessary gradients, and generic AI-generated dashboard aesthetics.

Prefer restrained corner radii, subtle depth, crisp alignment, and consistent spacing.

Use an 8-point spacing system wherever practical.

## Animation and interaction

Add subtle, professional motion:

- Sidebar and navigation transitions.
- Smooth page transitions where appropriate.
- Staggered dashboard card entrances.
- Gentle hover states.
- Animated status changes.
- Progress indicator transitions.
- Dropdown and modal transitions.
- Subtle button feedback.
- Respect the user's reduced-motion preference.

Animations should improve perceived quality without making the application slow or distracting.

## Quality benchmark

The finished application should look like a carefully designed, production-ready SaaS interface rather than a student exercise.

Prioritize visual consistency, information hierarchy, interaction quality, responsive behavior, and realistic product details.

# 25. FINAL QUALITY REQUIREMENTS

Prioritize the following:

1. Excellent visual design.
2. Complete, connected frontend workflows.
3. Consistent and believable demonstration data.
4. Clear distinction between student projects and general innovations.
5. Role-aware interfaces.
6. Constructive refinement rather than rejection-first design.
7. Clear routing and activity history.
8. Responsive layouts.
9. Maintainable React and TypeScript code.
10. Reliable functionality.

Avoid:

- A generic template dashboard with different colors.
- Excessive gradients and shadows.
- Too many oversized cards.
- Fake backend integrations.
- Hard-coded final organizational rules that have not been confirmed.
- Five fixed reviewers with an invented approval hierarchy.
- Making recommendation letters mandatory for every submission.
- Assigning student project codes to all general innovations.
- Allowing students to initiate the official brief contrary to the meeting notes.
- Placeholder actions that do nothing.
- Fake success messages suggesting that real people were notified.
- Overly complex animation that interferes with usability.

The product should feel like a credible institutional innovation management platform designed by an experienced product team.
